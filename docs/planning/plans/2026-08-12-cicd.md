# CI/CD Implementation Plan

**Goal:** Get the repo onto GitHub with a working 3-job Actions pipeline (lint, test, Docker build) gated on a reproducible dependency lockfile, and a README a visitor can use in under a minute.

**Architecture:** No new application code — this sub-project only touches project scaffolding (`pyproject.toml`, `.github/workflows/`, `Dockerfile`, `README.md`) plus mechanical lint fixes across the existing `src/`/`tests/` tree. A frozen `requirements-lock.txt`, generated from an isolated `.venv` (not the global interpreter), is the single dependency source of truth for CI and Docker.

**Tech Stack:** ruff (lint), GitHub Actions (`actions/checkout`, `actions/setup-python`), Docker, `gh` CLI.

## Global Constraints

- No Docker image push to a registry — build-only smoke test (spec: Non-goals, Component 3)
- CI trigger: `push` to `master` and `pull_request` (spec: Component 3)
- Python 3.13 only, no version matrix (spec: Component 3, Non-goals)
- `requirements-lock.txt` generated from an isolated `.venv`, never the global interpreter — amendment discovered during plan-writing: this machine's global `C:\Python313` has 335 unrelated packages installed (spec: Component 1 Amendment)
- Install sequence everywhere (CI + Docker): `pip install -r requirements-lock.txt` then `pip install --no-deps -e .` — the `--no-deps` is load-bearing, it must not trigger a second dependency resolution (spec: Component 1)
- `docker-compose.yml` is untouched by this sub-project (spec: Component 4)
- Repo name: `churn-mlops-forecasting-ops`, public, created via `gh repo create` (spec: Component 6)
- No AI co-author trailer on any commit — standing global rule, already followed on every commit in this project

## Prerequisite

An isolated `.venv/` already exists at the repo root (created during plan-writing) with `-e ".[dev]"` installed. Task 1 adds `ruff` to it and does the actual freeze — nothing else needs to happen before Task 1.

Open `requirements-lock.txt` and delete the line referencing this project's own editable install (starts with `-e ` or `# Editable Git install...`, naming `churn-mlops-forecasting-ops` or a local file path). **Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `requirements-lock.txt` (Task 1), a ruff-clean `src`/`tests` tree (Task 2), `Dockerfile` (Task 4 — the `docker-build` job builds it, so this file references a Dockerfile that must exist and build successfully by the time this workflow actually runs on GitHub; local task order doesn't block on this since nothing runs until Task 6's push).

- [ ] **Step 1: Write the workflow file**

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [master]
  pull_request:

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.13"
      - run: pip install -r requirements-lock.txt
      - run: pip install --no-deps -e .
      - run: ruff check src tests

  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.13"
      - run: pip install -r requirements-lock.txt
      - run: pip install --no-deps -e .
      - run: pytest -q

  docker-build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker build -t churn-mlops-forecasting-ops:ci .
```

````markdown
# churn-mlops-forecasting-ops

![CI](https://github.com/joshpeterpardosi/churn-mlops-forecasting-ops/actions/workflows/ci.yml/badge.svg)

An end-to-end MLOps loop for a SaaS subscription business: customer churn
prediction and MRR/revenue forecasting, built as one pipeline — data,
train, track, serve, monitor, retrain.

## Architecture

```
[Kaggle churn CSV] --+
                      |
[Synthetic MRR series] +--> Dagster asset pipeline
                      |
                 raw -> validate -> feature table
                      |
            +---------+---------+
            |                   |
     churn model           forecast model
     (classification)      (MRR / revenue, time series)
            |                   |
        MLflow tracking + model registry (both models)
            |
     FastAPI serving layer (Docker)
            |
     predictions log --> Evidently AI drift / perf reports
            |
     Dagster sensor watches drift threshold --> retrain trigger (loops back to training)
```

## What's here

| Stage | What it does |
|---|---|
| Data layer | Dagster assets: raw ingestion, validation, feature table join |
| Churn model | LightGBM classifier, tracked and auto-promoted via MLflow |
| Forecast model | LightGBM regression on lag features, same MLflow promotion path |
| Serving | FastAPI: `POST /predict/churn`, `GET /forecast/mrr?horizon=N` |
| Monitoring | Evidently drift reports + a Dagster sensor that triggers retraining |
| CI/CD | GitHub Actions: lint (ruff), test (pytest), Docker build |

Design docs and implementation plans for each stage are in
[`docs/planning/`](docs/planning/).

## Running it

```

## Requirements
````
